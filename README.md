# 時計塔領 — まだ見ぬ国の歴史

## 概要
時計塔領は、プレイヤーが国家の指導者となり「時計塔」を維持しつつ、税制や政策を通じて国家を運営するターン制シミュレーションゲームです。
- 目的：設定した任期（年数）を無事に全うし、挑戦目標や高いスコアを達成すること。
- 終了条件：時計塔のHPが0になる、革命や侵攻で敗北する、または任期を満了して結果画面に到達する。

## 主要な特徴
- 税率（消費税／所得税／住民税）の調整による国庫金・不満度・信頼度の変動。
- 毎ターン発生する季節イベント（災害）と、預言による予兆（オーメン）。
- 政策カード（例：時計塔修復、防災備蓄、教育投資、軍事訓練、臨時税、キャラバン）を1つ選択して実施。
- 信頼度・不満度・軍事力・塔HP・国庫金のバランスを取りながら統治を行う。
- スコア計算と評価（称号）で統治の出来を振り返れる。

## 遊び方（簡易）
1. 起動後、プレイ期間（年数）と難易度を設定して「統治を開始する」をクリック。
2. 各ターン（季節）ごとに：
   - 税率スライダーで税率を調整する（消費税・所得税・住民税）。
   - 今期の優先政策を1つ選ぶ（カードをクリック）。
   - 「次の季節へ」を押してターンを進める。
3. 画面右側の数値（国庫金・信頼度・不満度・軍事力）と時計塔HPを監視しつつ、政策と税率で安定を目指す。
4. 任期終了時に総合スコアが算出され、称号（例：覇王、名君、優良統治 など）が表示される。

## 操作方法（UI）
- マウス操作：スライダー操作、カード選択、ボタン（開始／次の季節／オプション／再挑戦）
- 全画面切替：画面上の「全画面表示」ボタン
- オプションでBGM／効果音のON/OFF切替、難易度設定の変更が可能

## ルールと仕様（詳細）
### ターンと季節
- 1ターンは1季節（春・夏・秋・冬）。UI上では「○年目 春」のように表示される。
- `max years` スライダーで設定した年数 ×4 が最大ターン数（`gameState.maxTurns`）。

### 税率と財政
- 各税率は初期値：消費税10%、所得税25%、住民税10%。
- 税率の変動は次ターンの国庫金に直接影響。
  - 設定値と標準値（消費10、所得25、住民10）の差分に応じて、`taxIncomeRates` の係数（config.js）を掛けた値が税収として反映される。
  - 例：消費差分 × `taxIncomeRates.consumption` が消費税からの税収。
- 税率上昇は一般に不満度を上げ、所得税は信頼度に強く影響する（`computeIncomeTaxTrustChange` に準拠）。

### 政策カード（効果の概略）
- 時計塔修復（repair）：国庫 -10 / 塔HP +18
- 防災備蓄（defense）：国庫 -7 / 災害耐性UP / 不満 -5
- 教育投資（education）：国庫 -8 / 信頼 +8 / 不満 -8
- 軍事訓練（train）：国庫 -10 / 軍事力 +10
- 臨時税（tempTax）：国庫 +15 / 信頼 -8 / 不満 +12
- キャラバン（caravan）：国庫 -18 / 信頼 +5 / 不満 -12

実際の数値やアルゴリズムは `gameLogic.js` と `state.js` の `computePredictedDeltas` / `processTurn` を参照してください。

### 災害・預言（オーメン）
- `seasonalEvents.omens` に定義された預言が毎ターンの予兆となる。オーメンは `tag` を持ち、災害判定の対象となる。
- 災害発生確率は難易度（`difficultyRates`）に依存し、難易度により被害の倍率や壊滅系イベント（cataclysm）の確率が変化します。
- 防災政策（`defense`）は特定の災害を無効化する挙動がある。

### 蜂起（革命）と他国の侵攻
- 信頼度が0になるか、不満度が高すぎると蜂起（革命）が発生する判定が行われる。
- 蜂起は政府の軍事力や信頼度に基づき鎮圧可否が決まる。失敗するとゲームオーバー（敗北）になります。
- 他国からの侵攻も条件に応じて発生し、軍事力や信頼度が防衛に影響します。

### 時計塔HP
- 毎ターン、塔HPは自然に減少（維持コスト）し、政策や災害で増減する。
- 塔HPが0になると時計塔は消失し、ゲームオーバーになります。

### スコア計算と評価
- `computeFinalScore`（`state.js`）により、国庫金・信頼度・軍事力・不満度から総合スコアを算出。
- スコアに基づき `scoreGradeMap`（`config.js`）の閾値で称号が付与される。

## 技術情報（ファイル構成）
- [index.html](index.html) — メインのHTML。UIと各DOM要素の配置。
- [style.css](style.css) — スタイル定義。

- [audio.js](audio.js) — BGM・効果音の管理（`GameAudioManager`）。
- [data.js](data.js) — ゲーム用の補助データ（存在する場合）。
- [test.html](test.html) — ブラウザでのテスト用HTML。
- [tests/balance.test.js](tests/balance.test.js) — Node環境でロジック単体の簡易バランス検証（VMで読み込み実行）。

## 実行方法（ローカルで試す）
1. 単純にブラウザで開く（簡易）
   - ファイルをブラウザで直接開き、`index.html` をロードしてください。ローカルファイル制約（Audio/モジュールなど）により挙動が制限される場合があります。

2. ローカルHTTPサーバで起動（推奨）

```bash
# Python 3 の簡易サーバ（ワークスペースのルートで実行）
python3 -m http.server 8000
# ブラウザで http://localhost:8000/index.html を開く
```

3. テスト（ロジック検証）
- `tests/balance.test.js` は Node の `vm` を使って `config.js` / `state.js` / `gameLogic.js` を読み込み、関数の出力をアサートしています。
- 実行方法（Node.js が必要）：

```bash
node tests/balance.test.js
```

## カスタマイズポイント（開発者向け）
- 難易度や税収係数、イベントテンプレートは [config.js](config.js) で調整できます。
- スコア算出ロジックは [state.js](state.js) の `computeFinalScore` を編集してください。
- 新しい政策カードを追加する場合は、`index.html` のカード要素と `gameLogic.js` の政策処理を同期して追加します。

## 既知の注意点
- 一部リソース（画像ファイル名など）がハードコーディングされています（例：`tower good.jpg` 等）。実行環境に画像が無い場合は表示や演出が簡素化されます。
- ブラウザのAudioポリシーにより、ユーザー操作（クリック）でBGMや効果音が初めて再生されます。
